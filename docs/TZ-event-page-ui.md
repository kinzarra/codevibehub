## 2. Превью YouTube: причина и исправление (приоритет 1)

**Причина.** Везде используется `https://i.ytimg.com/vi/<id>/hqdefault.jpg` — 480×360, формат 4:3. Для Shorts это кадр с чёрными полями: полезная область ≈ 200×360 px, а `object-fit: cover` растягивает её в карточку 9:16 (≈ 225×400 CSS px, при DPR 3 нужно 675×1200). Отсюда «мыло».

**Проверено curl'ом** (оба ID): `oar2.jpg` → 200, 1080×1920 (вертикальное превью Shorts, ~135 KB); `maxresdefault.jpg` → 200, 1280×720; `sddefault.jpg` → 640×480; `oardefault.jpg` для одного ролика → 404. Отсутствующий вариант YouTube отдаёт **404 с заглушкой 120×90**, т.е. `error` на `<img>` срабатывает.

**Сделать.**
1. В `event.js` одна функция `thumbSources(v)`:
   - `short`: `oar2` → `maxresdefault` → `hqdefault`;
   - 16:9: `maxresdefault` → `sddefault` → `hqdefault`.
2. Применять цепочку через `addEventListener('error')` (inline-обработчики запрещены CSP) и дополнительно на `load`: если `naturalWidth <= 120` — переходить к следующему источнику. Использовать для: карточек рейла (`.vid img`), постера reel (`.reel-poster`), превью в редакторе.
3. В `event.html` сразу ставить лучший источник в `src` (`oar2` для short, `maxresdefault` иначе) и корректные `width/height` (1080×1920 / 1280×720), чтобы без JS и до JS не было CLS и мыла. Первые две карточки — `fetchpriority="high"` без `loading="lazy"`, остальные — `loading="lazy"`.
4. Размытый фон слайда в reel (`--thumb`) — брать **`default.jpg` (120×90)**: под blur качество не нужно, экономим трафик и GPU.
5. Сам плеер: качество выбирает YouTube по размеру iframe. На телефоне кадр Short должен занимать всю ширину экрана (см. §4), iframe не масштабировать CSS-transform'ом. Параметр `vq` не использовать (игнорируется).

## 3. Плавность на смартфоне (приоритет 2)

Целевой аппарат: iPhone 14 (390×844, DPR 3) и средний Android. Убрать всё, что заставляет GPU перерисовывать полный экран.

1. `.reel-slide::before` — `filter: blur(60px)` + `transform: scale(1.1)` на полноэкранном элементе **у каждого слайда**. Заменить: фон рендерить только у текущего слайда и соседей (класс `.is-near`, ставить из `setCurrent`), blur ≤ 24px на `default.jpg`, `will-change: transform`. На `max-width: 760px` допустимо вместо blur-картинки взять статичный `radial-gradient` на токенах.
2. `backdrop-filter` в reel (progress, top, side, caption, hint, start-кнопка) — 6+ слоёв поверх скроллящегося контейнера. На `(hover: none)` или `max-width: 760px` заменить на полупрозрачные непрозрачные фоны (`#0B0B11D9`), backdrop-filter оставить только для десктопа. В рейле backdrop-filter только у `.vid-play`.
3. `dialog.reel[open]` анимация `scale(.97)` на 100dvh — на мобиле только `opacity`.
4. `.vid img`: убрать transition по `filter`; hover-эффекты уже под `@media (hover: hover)` — проверить, что `transform` на touch не срабатывает нигде в секциях agenda/pills/speakers.
5. `content-visibility: auto` на `.reel-slide` внутри snap-контейнера — проверить на прыжки скролла; если есть, убрать (ленивая загрузка iframe уже реализована).
6. `touch-action: pan-y` на `.reel-track`, `pan-x` на `.vids-rail`; `overscroll-behavior` уже стоит.
7. При открытом reel скрывать глобальные фоны: `html:has(dialog.reel[open]) :is(.grid-bg, .glow) { display: none }` — `.grid-bg` анимируется бесконечно (`drift`) и рисуется под диалогом.
8. **`viewport-fit=cover` отсутствует в meta viewport** → все `env(safe-area-inset-*)` сейчас равны 0. Добавить в `base.html`, затем проверить header/footer на iPhone (notch, home indicator), чтобы ничего не уехало.
9. `prefers-reduced-motion` глобально уже отключает анимации (`landing.css:183`) — новые анимации тоже должны под него попадать.

## 4. Визуальный апгрейд

Принцип: сдержанный премиум — стекло, тонкие ободки `#FFFFFF1C`, мягкие тени, mono-лейблы, акцентные градиенты только на действиях. Не добавлять новых цветов. Единые радиусы: карточки 20/24px, кнопки 999px. Шаг между секциями `clamp(40px, 8vw, 72px)`.

**Hero.** Градиентный заголовок оставить. `.ev-when` — одна стеклянная карточка с двумя ячейками, mono-лейблы, `tabular-nums` на отсчёте. На мобиле primary-кнопка на всю ширину (есть), ghost-кнопки в два столбца. `.lead` 17–18px / 1.5.

**Видео-рейл.**
- Мобила, ≤ 2 роликов: вместо рейла с обрезкой — сетка `repeat(2, 1fr)`, карточки 9:16 на всю ширину контейнера. ≥ 3 роликов — рейл с `scroll-snap-align: center` и «подглядыванием» следующей карточки ~12%.
- Десктоп: рейл как сейчас, стрелки, mask по краям.
- Карточка: тонкий ободок + `inset 0 1px 0 #FFFFFF18`, градиент снизу под заголовок, заголовок 2 строки (`-webkit-line-clamp: 2`), бейдж «Shorts» с мини-иконкой, номер `01`. Play 56px, стекло на десктопе / `#FFFFFF2E` + border на мобиле. Shimmer-скелет до загрузки превью (класс `is-loaded` по `load`).
- Шапка секции: «Видео» + счётчик-пилюля + компактная градиентная «Смотреть подряд» (иконка + текст; на мобиле `min-height: 40px`).

**Reel (полноэкранный просмотр).**
- Телефон: кадр Short во всю ширину (`--fw: 100vw`), без радиуса и рамки, как в YouTube Shorts; подпись поверх кадра снизу на `linear-gradient(transparent, #000A)`: заголовок 2 строки + компактная кнопка «YouTube». Боковые стрелки скрыть на `(hover: none)` — есть жесты. 16:9 видео на телефоне — по центру, с подписью под кадром.
- Десктоп: карточка 9:16 / 16:9 с тенью, стрелки справа, как сейчас.
- Верх: прогресс-полоски, счётчик `01 / 02`, крестик 44px — все с safe-area отступами.
- Подсказку «Листайте вверх-вниз» показывать один раз (`localStorage` ключ `reel-hint-seen`, в try/catch).
- Закрытие: Esc, крестик, системная «назад» (pushState при открытии → popstate закрывает) — проверить, что работает; если нет — сделать.

**Остальные секции** (Что разберём, Для кого, Спикеры, CTA): выровнять радиусы/отступы/размер `h2` (`clamp(24px, 4vw, 36px)`), убрать hover-сдвиги на touch, проверить читаемость на 390px: ничего не обрезается, горизонтального скролла страницы нет (`body` без переполнения).
